# uv って何？ pip と何が違うの？

## ひとことで言うと

**uv** は、Python の「本体」と「ライブラリ」をまとめて準備してくれる道具です。
**pip** はライブラリをインストールするだけの道具です。

## まず「ライブラリ」とは

Python で使える便利な部品集です。
この環境では `mcpi`（マイクラを操作するための部品集）を使っています。

```python
from mcpi.minecraft import Minecraft  # ← mcpi ライブラリを使う
```

ライブラリは Python に最初から入っていないので、インストールする必要があります。

## pip だと何が大変？

pip を使う場合は、こんな手順になります。

```bash
# 1. Python を自分でインストールする（バージョンは人によってバラバラ）
# 2. このフォルダ専用の環境を作る
python -m venv .venv
# 3. その環境を有効にする（Mac と Windows でコマンドが違う）
source .venv/bin/activate        # Mac
.venv\Scripts\activate           # Windows
# 4. ライブラリをインストールする
pip install mcpi
```

みんなで同じ環境を使おうとすると、こんな問題が起きやすくなります。

- 人によって Python のバージョンが違う
- 「環境を有効にする」のを忘れて、別の場所にインストールしてしまう
- インストールした時期によって、ライブラリのバージョンが違う
- 「私の PC では動くのに…」が起きる

## uv だとどうなる？

```bash
uv sync                           # 準備（初回のみ）
uv run python scripts/sample.py   # 実行
```

これだけです。`uv sync` が次のことを全部やってくれます。

1. 決められたバージョンの Python（3.12）を用意する（PC に入っていなければダウンロードする）
2. このフォルダ専用の環境（`.venv`）を作る
3. 決められたバージョンの `mcpi` をインストールする

`uv run` を付けて実行すると、自動でその専用環境が使われます。「有効にする」手順はいりません。

## たとえるなら「買い物メモ」と「レシート」

| | pip | uv |
|---|---|---|
| 買い物のしかた | 各自がお店に行って「mcpi ください」と買う | 共有の買い物メモとレシートを見て、全員が同じものをそろえる |
| 結果 | 買った時期や店によって中身が違うことがある | **全員まったく同じものがそろう** |

uv では、このリポジトリに入っている3つのファイルが「メモ」と「レシート」の役割をしています。

| ファイル | たとえ | 中身 |
|---|---|---|
| `pyproject.toml` | 買い物メモ | 「mcpi が必要」 |
| `uv.lock` | レシート | 「mcpi のバージョン 1.2.1 を、ここから入手した」という正確な記録 |
| `.python-version` | 「この型の鍋を使う」というメモ | 「Python 3.12 を使う」 |

GitHub からこのリポジトリを持ってきた人は、`uv sync` するだけでレシートどおりの環境がそろいます。

## pip との比較まとめ

| | pip | uv |
|---|---|---|
| Python 本体の準備 | 自分でインストール | 自動 |
| 専用環境（.venv）の作成 | 自分でコマンドを打つ | 自動 |
| 環境の有効化 | 毎回必要（忘れやすい） | 不要（`uv run` を付けるだけ） |
| バージョンの固定 | 別途工夫が必要 | `uv.lock` で自動 |
| 速さ | ふつう | とても速い |

## よく使うコマンド

| コマンド | 意味 |
|---|---|
| `uv sync` | `uv.lock` どおりに環境をそろえる |
| `uv run python ファイル名.py` | 専用環境で Python を実行する |
| `uv add ライブラリ名` | ライブラリを追加する（`pyproject.toml` と `uv.lock` が自動で更新される） |
| `uv remove ライブラリ名` | ライブラリを削除する |

> ライブラリを追加・削除したら、`pyproject.toml` と `uv.lock` の **両方を GitHub にコミット** してください。
> そうすれば、他の人も `uv sync` するだけで同じ環境になります。

## まとめ

- pip はライブラリを入れるだけ。Python 本体や環境の準備は自分でやる
- uv は Python 本体・専用環境・ライブラリをまとめて準備してくれる
- `uv.lock` があるので、GitHub で共有しても全員が同じ環境になる
- 実行するときは `uv run python ファイル名.py`
